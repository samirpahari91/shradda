STEP 1 -- SET YOUR GIT IDENTITY  (required before any commit)
================================================================================
Git refuses to commit without a name and email. Pick ONE of these.

  OPTION A (recommended) -- keep your real email private.
  GitHub can accept a noreply address that still links commits to your account.
  Find yours at: github.com -> Settings -> Emails -> "Keep my email addresses
  private". It looks like  12345678+<USER>@users.noreply.github.com

    git config --global user.name "Your Name"
    git config --global user.email "12345678+<USER>@users.noreply.github.com"

  OPTION B -- use your real email (it will be visible in public commit history):

    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"

  OPTION C -- this repository only, leaving your global config untouched.
  Run these from inside D:\Shraddha\Thesis_New, note there is no --global:

    git config user.name "Your Name"
    git config user.email "you@example.com"

CHECK:
    git config user.name
    git config user.email
  -> both print what you set, neither is blank

!! Whatever email you use here must be one GitHub knows about, or your commits
   will show up as an unlinked author rather than as you.

STEP 4 -- CONNECT AND PUSH
================================================================================
    git remote add origin https://github.com/<USER>/<REPO>.git
    git push -u origin main

  Authentication, first time only. A browser window or a credential dialog will
  open. Sign in to GitHub and approve.

!! If you are asked for a PASSWORD in the terminal, do NOT type your GitHub
   account password -- GitHub removed password authentication for git in 2021.
   Use a Personal Access Token as the password instead:
       github.com -> Settings -> Developer settings ->
       Personal access tokens -> Tokens (classic) -> Generate new token
       Scope needed: "repo".  Copy the token and paste it as the password.
   Windows will normally remember it via the built-in credential manager.

CHECK:
    git remote -v
  -> origin  https://github.com/<USER>/<REPO>.git  (fetch and push)
    git status
  -> "Your branch is up to date with 'origin/main'"

  Then open https://github.com/<USER>/<REPO> in a browser. You should see your
  files, including the docs/ folder. Confirm docs/model.json is listed at
  roughly 4.8 MB.

!! GitHub may warn that model.json is large. 4.8 MB is fine -- the hard limit is
   100 MB and the advisory warning starts at 50 MB.
!! Do NOT move model.json into Git LFS. GitHub Pages does not resolve LFS
   pointers, so the deployed site would fetch a text stub and the app would
   fail to load with no obvious cause.

STEP 5 -- TURN ON GITHUB PAGES
================================================================================
  5.1  Your repo on github.com -> Settings (top bar) -> Pages (left sidebar)
  5.2  Under "Build and deployment":
         Source = Deploy from a branch
         Branch = main        Folder = /docs        <-- NOT / (root)
  5.3  Click Save.
  5.4  Wait 1-3 minutes. Watch progress in the Actions tab. When it finishes,
       the Pages settings screen shows a green banner with your live URL:

         https://<USER>.github.io/<REPO>/

!! Choosing Folder = / instead of /docs is the single most common mistake here.
   The symptom is a page that loads but shows the error panel, because
   model.json 404s.

ROUTINE UPDATES AFTER THIS
================================================================================
Once set up, publishing a change is three commands. Run the gates FIRST:

    python _check_docs.py
    node verify_js.mjs
    python _check_nb.py

  All three must print OK/PASS and exit 0. Then:

!! Never push on a failing gate. A verify_js.mjs failure specifically means
   browser visitors would see different predictions than your thesis reports --
   and nothing about the page would look broken, so no one would notice.

================================================================================
IF SOMETHING GOES WRONG
================================================================================
"fatal: ambiguous argument 'HEAD'"
    You have no commits yet. Do Step 2.

"Updates were rejected because the remote contains work you do not have"
    You let GitHub create a README/.gitignore/license in Step 3. Easiest fix is
    to delete the GitHub repo and redo Step 3 with all boxes unchecked. Do NOT
    use `git push --force` unless you are certain the remote holds nothing you
    want.

"Support for password authentication was removed"
    Use a Personal Access Token as the password. See the note in Step 4.

Live site shows the error panel instead of predictions
    Almost always Folder = / instead of /docs in Step 5.2. Also check the
    Network tab for a 404 on model.json.

Live site 404s entirely
    Pages has not finished its first deployment, or the repo is private. Check
    the Actions tab, and confirm visibility is Public.

Everything works locally but not deployed
    Hard-reload (Ctrl+F5). If it persists, confirm the commit that fixed it was
    actually pushed:  git log origin/main --oneline -1
